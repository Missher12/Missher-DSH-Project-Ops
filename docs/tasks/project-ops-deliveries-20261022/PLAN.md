# Project Ops 交付总览与标题输入修正（静态候选）

状态：**静态候选，未验证、未冻结、未发布**。本文件记录 2026-10-22 一次性静态实现回合的计划；测试/构建/隔离 Host 由根串行租约安排，Codex 独立审查。

## 需求

用户原话："那个 ops 运行的时候 偶尔会 Error: Invalid title: provide 1–16000 characters 然后我想彻底优化一下 所有的交付 这里都能显示。"

1. 修正 `document_write` 的输入契约与 Agent 指引，使局部进展更新不再因为缺少 `title` 失败；错误必须带字段名与补救提示，不伪造、不截断、不吞错。
2. 面板按"当前工作区全部已记录交付"展示：根 `PLAN.md`/`READY.md` 与 `docs/tasks` 下任何含文档的目录，不再靠 16 位摘要命名过滤隐藏历史交付。
3. 保留既有语义：CAS/owner/原子写/失败取消状态/READY 恢复、客户端主题与键盘行为、0.4.1 已接受的标题栏 `align-self` 变量修复。
4. 只改本仓库 `src`、针对性 `tests`、相关 `docs`；本轮不执行任何测试、`tsc`、构建、打包、Host 启动或 Git 写操作。

## 设计

- **输入契约**：`begin` 仍要求六个字段（`title`、`requirements`、`design`、`steps[]`、`acceptance[]`、`progress`），但工具描述与 systemPrompt 指引明确列出并给出最小合法示例，补上原先漏列的 `title`。`update` 改为在读取记录并校验 `expectedRevision` **之后**用 `mergePlan` 合并：只有字段缺省（`undefined`）保留原值；`null`、空串、错误类型、超限与未知字段按字段名拒绝。修订校验前移，旧修订即使提交相同内容或空对象也会被拒绝，不会伪装成 no-op 成功。
- **发现**：客户端读取工作区根与 `docs/tasks` 的直接子目录；目录含 `PLAN.md` 或 `READY.md` 即入列（新命名、旧命名、人工普通记录、孤立 READY 一律可见）。无托管元数据标"普通记录/待核对"；元数据头存在但不合法标"待核对/损坏"；单个目录或文档读取失败保留该行并显示原因；`docs/tasks` 列表失败仍保留根记录并给出告警。
- **分页**：宿主 `remote.workspaceFiles.list` 没有游标，因此由客户端维护"加载代"目录快照：首批读取根与 `docs/tasks` 列表并保存于该 session 的 Face 闭包，后续批次只按偏移处理同一快照；刷新（offset 0）或会话切换才建新快照，两个会话交错加载互不覆盖。宿主列表自身的 `truncated` 明确提示，不再有静默的前 100 项截断。
- **展示**：行标题、相对位置与来源标签、四态（交付关联当前方案/方案已更新/记录待核对/方案进行中）、方案与交付入口；托管交付的产物与验收句标为"会话报告"，产物不是链接、不会自动打开，摘要截断提示"完整内容见 READY"，待核对/缺失状态不显示旧验收句。本批已加载记录由本地检索框按标题/目录名/路径筛选，检索输入加入既有 Tab 焦点遍历。

## 验收标准

1. 局部 `update` 只传 `progress` 即可成功，其余字段保持不变；完整六字段调用继续兼容。
2. `begin` 缺 `title` 时错误明确指出字段缺失与补救方式；`null`/空串/错误类型/未知字段/旧修订（含相同内容与空 patch）均被拒绝且不写文件。
3. 根 READY、孤立 READY、旧命名目录、普通记录、损坏元数据均可见且状态准确；`docs/tasks` 列表失败仍显示根记录与告警。
4. 分页游标在同一加载代内稳定（目录增删不重复/不漏项），两个会话交错加载互不干扰；宿主截断明确提示；不再有静默 100 项上限。
5. 托管交付的产物与验收句明确标为会话报告；截断时提示完整内容在 READY；待核对/缺失不冒称当前验收有效。
6. 既有测试与新增测试通过，类型检查通过，构建产物与包检查通过（待执行）。
