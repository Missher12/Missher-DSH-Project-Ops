# Project Ops：开发方案与交付记录

## 需求与边界

升级同一 Project Ops 项目为 @missher/dsh-project-ops（主显示名 Project Ops），保留声明任务发现、执行、回执、验证门等原有能力。在真实开发任务中维护独立 PLAN.md，交付检查后生成 READY.md，提供可发现的项目任务、查看方案、查看交付入口。不增加模型调用或调度器；不将回复结束或任意工具退出视为开发完成。沿用 Host 会话身份、工具权限、沙箱与文件系统；不自动推 Git。

## 基线与归属

正式仓库 https://github.com/Missher12/Missher-DSH-Project-Ops；2026-10-12 新克隆 HEAD 44fc988f511f1d16f6b8ff29de03dacdc36aa58c，源码 0.3.1，初始工作树干净且无仓库 AGENTS.md。只写本独立仓库；桌面任务独占公共 Host、最终 Git/Release/日常安装。新版 Host 当前参考官方 0.2.1-alpha.2，最终组合须重新绑定精确包。

## 实现方案

- 基于实际 Host API 升级依赖和适配；通过原生会话及首次工具调用标识绑定任务，不创建第二套任务执行器。
- 每任务独立目录，固定模板和受保护的管理信息，人工编辑与新鲜度冲突必须明确失败；通过原生文件工具和原子版本守卫落盘，重启从文件恢复。
- 显式开发/进展/交付工具与短指引驱动生命周期；普通问答和极小修改不强制生成文档。已授权开发生成方案后继续。
- READY 分别列出实现、验证、产物、Git、发布、安装与限制，未知证据不能标通过；失败/取消保留事实。
- 使用现有客户端扩展点及 Host 文件预览能力提供入口，不改共享 Host。

### 实际界面验收发现的补充修正

原生 Markdown 预览把 HTML 注释元数据渲染成正文；改为未被引用的标准 Markdown 链接定义保存管理信息，避免遮挡业务内容。浮层固定在视口内并在打开文件时收起。客户端内部 React 组件停止公开导出，严格消费者检查覆盖主入口、Cordis与客户端入口。构建输出只在入口清理一次，避免两个并行配置清理重叠目录。
